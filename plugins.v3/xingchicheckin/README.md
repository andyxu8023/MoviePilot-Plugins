# 星驰 API 签到（XingchiCheckin）

用登录后的会话令牌，每天定时给 **星驰API**（`xingchiapi.com`）做一次签到：先续期会话、再提交签到，不参与抽奖，也不碰站点其它接口。

适用前提：你已经在浏览器里登录过该站点，能拿到 `refresh_token`。插件不做登录、不接验证码，只负责「续期 + 签到」。

## 它解决什么

站点的签到要登录态，而登录会话会过期。手动做法是每天打开页面点一次；本插件把这件事变成：每次运行先用 `refresh_token` 换一次新会话，再用新令牌调签到接口，并把站点轮换出来的**新 `refresh_token` 立刻写回插件配置**。于是只要站点侧没有强制重新登录，你配一次就能长期跑。

## 配置项

| 字段 | 说明 |
| --- | --- |
| 启用自动签到 | 关掉后不再注册定时服务 |
| 签到时间 | 五段 Cron，**按北京时间**填写（注意 MoviePilot 的星期字段 `0=周一`，与 Linux crontab 的 `0=周日` 不同） |
| 会话令牌 `refresh_token` | 密码框显示。**由插件自动轮换维护**，正常情况下你只需要在第一次或会话彻底失效时填一次 |
| 发送签到结果和会话失效通知 | 开关。通知不指定渠道，沿用宿主「系统设置 → 通知渠道」里已启用的全部渠道 |

## 令牌怎么取

登录站点后按 F12 打开开发者工具 → **Application（应用）→ Local Storage → `https://xingchiapi.com`**，取键 **`refresh_token`** 的值，粘贴到配置项保存即可。

- 同一份存储里还有 `auth_token`，那是短期访问令牌，**不要填它** —— 插件每轮都会自己用 `refresh_token` 换取。
- 站点前端把会话存在 localStorage 的 `refresh_token` / `auth_token` / `auth_user` / `token_expires_at` 几项里，退出登录会一并清掉，届时需要重新登录再取新值。
- 也可以在 Network 里找一次 `POST /api/v1/auth/refresh`，请求体里的 `refresh_token` 同样可用。

注意：

- 令牌是**一次性轮换**的。签到成功后旧值即作废，配置里存的永远是最新那枚，不要把旧值另存后回头再填。
- 配置里留空保存时，插件会沿用内存里最近一次轮换出的令牌（防止表单误清）；确实要彻底清除，请先停用插件再重新加载。

## 一次签到做了什么

1. `POST /api/v1/auth/refresh`：用 `refresh_token` 换新会话，拿到 `access_token` 与新的 `refresh_token`。
2. **先保存新令牌**（写回插件配置），再往下走 —— 即使后面签到失败，会话也不会丢。
3. `GET /api/v1/user/checkin?timezone=Asia/Shanghai`：读今日状态。站点没开签到、或今日已签到，就**不再提交**。
4. `POST /api/v1/user/checkin`：提交并确认结果，奖励值会写进通知文本。

整个过程在同一进程内加锁，重复触发不会并发跑。

## 失败时的口径

| 现象 | 含义 / 处理 |
| --- | --- |
| `续期被拒绝（HTTP 401/403）` | 会话彻底失效，需要重新登录站点并更新配置里的 `refresh_token` |
| `站点返回重定向（HTTP 3xx），未跟随` | 接口路径或站点网关有变，插件刻意不跟随重定向，避免把令牌发给别的地址 |
| `站点连接失败（…）` | 网络或代理问题；代理沿用 MoviePilot 的 `PROXY_HOST`，`socks5://` 会按 `socks5h` 处理，宿主缺 SOCKS 支持时会明确报错 |
| `站点未返回可识别的签到状态，未提交签到` | 接口返回结构变了，插件**宁可不提交**也不猜状态 |
| `轮换后的令牌保存失败`（日志） | 配置写回失败，下次加载可能要求重新登录；检查数据库写入 |

失败不做即时重试，等下一个 Cron 周期；结果与最近一次运行文本都会显示在详情页，并（可选）推送通知。

## 关于旧版本

v1.0.x 把令牌存在插件数据目录的 `refresh_token` 文件里。v1.1.0 起改为**存在插件配置里**：首次加载时自动把旧文件迁移进配置，迁移成功后删除该文件；迁移失败会保留文件并在日志里提示。

## 依赖

无新增第三方依赖，使用宿主已有的 `requests` 与 `apscheduler`。
